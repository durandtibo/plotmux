    plotmux.specs.base ¶

    Contain the base classes of the backend-agnostic marks.

    plotmux.specs.base.MarkSpec dataclass ¶

    Bases: Spec

    Define the base class of the marks: what is drawn on an axes.

    A mark is plain, backend-agnostic data (the data and the style of one chart type). It never holds a plotting-library object. The axes (title, labels, scales, limits, legend) belong to a PanelSpec, not to the mark. A mark turns itself into drawing primitives (see to_primitives), so a new chart type is one subclass of MarkSpec and needs no change in a backend when it is a composition of Bars, Line and Points.

    A subclass that has its own __post_init__ must call super().__post_init__().

    Parameters:

    Name Type Description Default
    label str | None

    An optional label used in the legend.

    		 None
    color Color

    An optional color. It can be a hex string ("#rrggbb" or "#rrggbbaa"), a CSS/matplotlib named color (e.g. "tab:blue"), or an RGB(A) tuple of floats in [0, 1]. None takes the next color of plotmux.colors.palette.DEFAULT_PALETTE (see plotmux.scene.build_scene), the same on every backend.

    		 None
    alpha float | None

    An optional opacity, in [0, 1]. None uses the backend's default (fully opaque).

    		 None

    Raises:

    Type Description
    InvalidSpecError

    if alpha is not in [0, 1]. Also a ValueError.
    InvalidColorError

    if color is not a valid color. Also a ValueError.

    plotmux.specs.base.Spec dataclass ¶

    Bases: ValueObject

    Define the base class of the immutable value objects of the specs.

    A spec cannot change after its construction: the fields are frozen and the arrays are copied and read-only (see plotmux.utils.to_readonly_array). Two specs are equal if they have the same type and equal fields, where arrays are compared by value (a plain dataclass == raises on an array field). A spec holds arrays, so it is not hashable.

    Example 
    >>> import numpy as np
>>> from plotmux.specs import LineSpec
>>> LineSpec(x=np.arange(3), y=np.arange(3)) == LineSpec(x=np.arange(3), y=np.arange(3))
True
>>> LineSpec(x=np.arange(3), y=np.arange(3)) == LineSpec(x=np.arange(3), y=np.arange(1, 4))
False

    plotmux.specs.panel.PanelSpec dataclass ¶

    Bases: Spec

    Define one axes: the marks drawn on it and its style.

    Several marks on one panel are drawn on shared axes (a layer). The marks and the axes style are the only fields: the axes style exists once, here, and not on each mark.

    Parameters:

    Name Type Description Default
    marks tuple[MarkSpec, ...]

    The marks to draw, in drawing order. Must be non-empty. A panel holds marks only, so a panel cannot nest.

    		 required
    title str | None

    An optional axes title.

    		 None
    xlabel str | None

    An optional x-axis label.

    		 None
    ylabel str | None

    An optional y-axis label.

    		 None
    xscale Literal['linear', 'log']

    The x-axis scale, "linear" or "log".

    		 'linear'
    yscale Literal['linear', 'log']

    The y-axis scale, "linear" or "log".

    		 'linear'
    xmin float | None

    An optional lower limit of the x-axis. A number, not a quantile string. None leaves the axis autoscaled.

    		 None
    xmax float | None

    An optional upper limit of the x-axis.

    		 None
    ymin float | None

    An optional lower limit of the y-axis.

    		 None
    ymax float | None

    An optional upper limit of the y-axis.

    		 None
    background_color Color

    An optional background color of the axes. Same format as MarkSpec.color. None uses the backend's default.

    		 None
    legend_title str | None

    An optional heading of the legend box. The legend exists if and only if one mark has a label.

    		 None
    legend_location LegendLocation | None

    An optional legend position, one of LEGEND_LOCATIONS. None leaves the backend's default.

    		 None
    legend_orientation Literal['vertical', 'horizontal'] | None

    An optional legend layout, "vertical" or "horizontal". None leaves the backend's default.

    		 None

    Raises:

    Type Description
    InvalidSpecError

    if marks is empty or holds an object that is not a MarkSpec, a scale, a legend location or a legend orientation is not supported, xmin > xmax or ymin > ymax, the marks mix a categorical x with a numeric x, or a mark needs the x extent (a slope) and the panel has none. Also a ValueError.
    InvalidColorError

    if background_color is not a valid color. Also a ValueError.
    Example 
    >>> import numpy as np
>>> from plotmux.specs import HistogramSpec, LineSpec, PanelSpec
>>> spec = PanelSpec(
...     marks=(
...         HistogramSpec(values=np.arange(101), bins=10),
...         LineSpec(x=np.arange(10), y=np.arange(10)),
...     ),
...     title="two marks",
... )
>>> len(spec.marks)
2

    plotmux.specs.panel.PanelSpec.x_extent ¶

    x_extent() -> tuple[float, float] | None

    Resolve the x extent of the panel.

    Each bound is the explicit xmin/xmax where it is set, else the min/max of the x_extent() of the marks that have data on the x-axis.

    Returns:

    Type Description
    tuple[float, float] | None

    The (lo, hi) extent, or None if a bound can be resolved neither from the limits nor from the marks.
    Example 
    >>> import numpy as np
>>> from plotmux.specs import LineSpec, PanelSpec
>>> PanelSpec(marks=(LineSpec(x=np.arange(5), y=np.arange(5)),)).x_extent()

>>> PanelSpec(marks=(LineSpec(x=np.arange(5), y=np.arange(5)),), xmax=10).x_extent()
(0.0, 10)

    plotmux.specs.histogram ¶

    Contain the backend-agnostic histogram specification.

    plotmux.specs.histogram.HistogramSpec dataclass ¶

    Bases: MarkSpec

    Define a backend-agnostic histogram mark.

    Parameters:

    Name Type Description Default
    values ndarray

    The array of values to plot.

    		 required
    bins int

    The number of histogram bins. Must be a positive integer.

    		 30
    xmin float | str | None

    Specifies the lower bound of the range of the values that are binned. It can be an explicit value, a quantile string such as "q0.1", or None to use the minimum of values. See plotmux.utils.range.find_range for the exact semantics. It is not an axis limit (see PanelSpec.xmin): the axes autoscale on the bars.

    		 None
    xmax float | str | None

    Specifies the upper bound of the range of the values that are binned. Same semantics as xmin but for the upper bound.

    		 None
    density bool

    If True, each bin displays the bin's raw count divided by the total number of counts and the bin width, so that the area under the histogram integrates to 1.

    		 False

    label, color and alpha are inherited from MarkSpec. NaN and inf values of values are dropped, and a UserWarning with their count is emitted once, when the spec is built. The quantile bounds are computed on the finite values.

    Raises:

    Type Description
    InvalidSpecError

    if bins is not a positive integer, values is not 1-dimensional, is empty, is not numeric or has no finite value, or xmin and xmax are both explicit numeric values with xmin >= xmax. Also a ValueError.
    InvalidColorError

    if color is not a valid color. Also a ValueError.
    Example 
    >>> import numpy as np
>>> from plotmux.specs import HistogramSpec
>>> spec = HistogramSpec(values=np.arange(101), bins=10)
>>> spec.bins
10

    plotmux.specs.cdf ¶

    Contain the backend-agnostic empirical CDF specification.

    plotmux.specs.cdf.CdfSpec dataclass ¶

    Bases: MarkSpec

    Define a backend-agnostic empirical cumulative distribution function (CDF) mark.

    The curve is the exact empirical P(X <= x) over all the values: a step of 1 / n at each value. xmin and xmax restrict what is drawn, they do not renormalize the curve.

    Parameters:

    Name Type Description Default
    values ndarray

    The array of values to plot.

    		 required
    nbins int | None

    None for the exact CDF (2 n vertices), or a positive integer to bin the values first and bound the number of vertices (2 * nbins + 1) for a large input.

    		 None
    xmin float | str | None

    Specifies the lower bound of the part of the curve that is drawn. It can be an explicit value, a quantile string such as "q0.1", or None to use the minimum of values. See plotmux.utils.range.find_range for the exact semantics. It is not an axis limit (see PanelSpec.xmin).

    		 None
    xmax float | str | None

    Specifies the upper bound of the part of the curve that is drawn. Same semantics as xmin but for the upper bound.

    		 None

    label, color and alpha are inherited from MarkSpec. NaN and inf values of values are dropped, and a UserWarning with their count is emitted once, when the spec is built. The quantile bounds are computed on the finite values.

    Raises:

    Type Description
    InvalidSpecError

    if nbins is set and is not a positive integer, values is not 1-dimensional, is empty, is not numeric or has no finite value, or xmin and xmax are both explicit numeric values with xmin >= xmax. Also a ValueError.
    InvalidColorError

    if color is not a valid color. Also a ValueError.
    Example 
    >>> import numpy as np
>>> from plotmux.specs import CdfSpec
>>> spec = CdfSpec(values=np.arange(101), nbins=10)
>>> spec.nbins
10

    plotmux.specs.stacked_bar.StackedBarSpec dataclass ¶

    Bases: MarkSpec

    Define a backend-agnostic stacked-bar-chart mark.

    Each series is a segment stacked on top of the running total of the series before it, at each x position. The running total is a plain cumulative sum (negative values are not handled specially).

    Parameters:

    Name Type Description Default
    x ndarray

    The array of bar positions, shared by every series. Either numeric or an array of strings, drawn as a categorical x-axis, same semantics as BarSpec.x.

    		 required
    series tuple[BarSeries, ...]

    The series to stack, in stacking order (bottom to top). Must be non-empty, and every series' y must have the same length as x.

    		 required
    width float

    The width of each bar, in x data units (a fraction of the band for a categorical x). Must be a positive number.

    		 0.8

    alpha is inherited from MarkSpec and applies to every series. The label and the color are set on each BarSeries, not on the spec.

    Raises:

    Type Description
    InvalidSpecError

    if series is empty, any series' y does not have the same length as x, width is not a positive number, alpha is not in [0, 1], or label or color is set on the spec. Also a ValueError.
    Example

    plotmux.specs.slope ¶

    Contain the backend-agnostic slope (abline) specification.

    plotmux.specs.slope.SlopeSpec dataclass ¶

    Bases: MarkSpec

    Define a backend-agnostic slope (a.k.a. abline) mark.

    Unlike LineSpec, which is data-bound (an explicit x/y pair), a SlopeSpec describes a line by its closed form, y = gradient * x + intercept, with no data of its own. It is drawn as the segment over the x extent of its panel: the xmin/xmax of the PanelSpec where they are set, else the extent of the data of the other marks of the panel. A panel with a slope and no x extent raises an InvalidSpecError.

    Parameters:

    Name Type Description Default
    gradient float

    The line's slope.

    		 required
    intercept float

    The line's y-intercept (the y value at x = 0).

    		 0.0
    linewidth float | None

    An optional line width. None uses the backend's default width.

    		 None
    linestyle Literal['solid', 'dashed', 'dotted', 'dashdot']

    The line's dash style.

    		 'solid'

    label, color and alpha are inherited from MarkSpec.

    Raises:

    Type Description
    InvalidSpecError

    if alpha is not in [0, 1]. Also a ValueError.
    InvalidColorError

    if color is not a valid color. Also a ValueError.
    Example 
    >>> from plotmux.specs import SlopeSpec
>>> spec = SlopeSpec(gradient=2, intercept=10)
>>> spec.gradient
2

    plotmux.specs.grid ¶

    Contain the backend-agnostic grid-layout specification.

    plotmux.specs.grid.GridSpec dataclass ¶

    Bases: Spec

    Define a grid of independent panels.

    Each panel is its own axes with its own marks and style, the backend-agnostic equivalent of matplotlib's pyplot.subplots. A grid holds panels, and a panel holds marks, so neither a grid in a grid nor a panel in a panel can be built.

    Parameters:

    Name Type Description Default
    panels tuple[PanelSpec, ...]

    The panels to draw, in row-major order (left to right, top to bottom). Must be non-empty.

    		 required
    ncols int

    The number of columns in the grid. The last row is left short when len(panels) is not a multiple of ncols. Must be a positive integer.

    		 1
    title str | None

    An optional title shown once above the whole grid.

    		 None

    Raises:

    Type Description
    InvalidSpecError

    if panels is empty or holds an object that is not a PanelSpec, or ncols is not a positive integer. Also a ValueError.
    Example 
    >>> import numpy as np
>>> from plotmux.specs import GridSpec, HistogramSpec, LineSpec, PanelSpec
>>> spec = GridSpec(
...     panels=(
...         PanelSpec(marks=(HistogramSpec(values=np.arange(101), bins=10),)),
...         PanelSpec(marks=(LineSpec(x=np.arange(10), y=np.arange(10)),)),
...     ),
...     ncols=2,
... )
>>> len(spec.panels)
2
